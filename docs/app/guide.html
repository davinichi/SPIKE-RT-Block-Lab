SBL-RT Windows 0.3.0 導入・復帰ガイド

ブロック編集 ／ DFU・USBログ ／ Windows版のダウンロード

実機未検証の試作版です。この版でのHub起動・停止・書き込み・復帰は、まだ実機確認していません。ビルドの成功と実機動作の確認を区別します。

対応する機器と機能

対象はSPIKE Prime Large Hubです。A〜Eポートを使い、単一スタート、数値変数・演算・分岐・ループ、1個/2個のモーター、追加センサー、表示・ランプ・音、数値引数２個と戻り値１個のマイブロックに対応します。パレットはSBL保存版23と同じ15グループ・順番・文言です。未対応命令は警告を表示し、編集・保存・読込はできますがC生成を止めます。

SBLとの比較・対応表で単位・引数・制限・未対応機能を確認できます。同期走行、イベント、姿勢・色番号、PID、CSV、文字変数・リスト、SBL/EBL作品の直接読込や４環境互換は未対応です。

Windows版の起動

  1. Releasesから SBL-RT-Windows-0.3.0.zip を取得し、書き込み可能なフォルダーにすべて展開します。
  2. SBL-RT.exeを起動します。exeだけを別の場所へ移動しないでください。インストールと管理者権限は不要です。未署名版のため組織の実行制限がある場合は管理者の運用に従ってください。
  3. 最初は「表示のみ」サンプルを使います。作品を .sblrt でPCに保存し、「CソースZIPを保存」で３つのCファイルと構成ファイルを取得できます。

ブロック編集とC生成はオフラインで使えます。DFU・ログはアプリの「DFU・ログ画面を開く」からChrome / Edgeで利用します。ローカル画面を使う間はWindowsアプリを開いたままにします。

ポートFについて

公式SPIKE-RT v0.2.0では、FはASP3デバッグUART用に予約されています。本版はA〜Eのみ対応し、Fを使う作品も値を保持して編集・保存・読込できますが、C生成は禁止します。ご紹介いただいたQiita記事と固定版の公式依存ソースを照合して訂正しました。記事のF開放はSDKの複数ファイルとUART設定の変更を伴う非公式手順です。標準版には適用せず、将来の別プロファイルとして検討します。

コンパイルの準備

アプリにSPIKE-RTの完全なコンパイラ環境は同梱していません。ローカルビルドには、準備済みDocker、Git、依存サブモジュールを含むSPIKE-RT v0.2.0 SDK、公式コンテナが必要です。アプリはそれらを自動インストールしません。

管理者・利用者が準備を確認したうえで、公式資料に沿って別途取得します。

git clone --branch v0.2.0 https://github.com/spike-rt/spike-rt.git
cd spike-rt
git submodule update --init
docker pull ghcr.io/spike-rt/spike-rt:rich

「ローカルDockerでビルド」でSDKフォルダーを選択します。アプリはコピー内でビルドし、元のSDKには出力しません。ビルド結果はアプリのユーザーデータ内に保存され、画面に asp.bin の保存先・SHA-256を表示します。既存イメージのIDを記録し、ビルド中のコンテナ通信は無効にしています。

GitHub Actionsで表示・マイブロック・モーター・距離・演算・角度動作・センサーの７サンプルを、公式v0.2.0とARM GCC 10.3でビルドできました（実機未検証）。Releasesの SBL-RT-sample-firmware.zip にも配布します。最初は display.bin だけを試してください。緑の実行のArtifactsから sample-firmware を取得できます。これは編集した自分の作品のビルドとは別です。

Hubの事前準備とデータへの影響

  1. Hub内の作品、設定、ログは失われる前提で、標準SPIKEアプリやSBLからPCに作品を保存します。SPIKE-RT用asp.binは標準Hub OSを置き換えます。標準OSの通常更新で作品が残るという説明を、この書き換えに適用しないでください。
  2. バッテリーを充電し、データ通信対応USBケーブルを用意します。他のSPIKE・Pybricks画面やCOM接続を閉じます。
  3. 最初はモーター・センサーを外し、表示のみのプログラムで試します。復帰方法と、必要に応じて管理者が対応できることを先に確認します。
  4. WindowsでDFUにWinUSBドライバーが必要となる場合があります。アプリはドライバーやセキュリティ設定を変更しません。対象のHubのDFUインターフェースだけを確認し、組織の承認に従ってください。他のUSB機器やUSBコントローラーへ変更を適用しないでください。

DFUモードにして書き込む

  1. USBを外しHubの電源を切ります。
  2. Bluetoothの接続ボタンを押しながらUSBをPCにつなぎます。接続LEDが点滅するまで押し続けます。これはSPIKE-RT公式のDFU手順です。
  3. 「DFU・ログ画面」でコンパイル済み asp.bin を選び、ファイルのサイズとSHA-256を確認します。未知のバイナリーを使わないでください。
  4. バックアップ・復帰手順の確認欄にチェックし、「DFUのHubを選択」で自分のHubを選びます。「確認して書き込む」で最終確認して開始します。
  5. 書き込み中はUSBを抜かないでください。終了後、再起動してUSBログで READY を確認します。中央ボタンを一度押して離すと作品が開始します。実行中に中央ボタンを押すと停止処理へ進みます。

書き込み先は 0x08008000、最大992KiB。既存Toolkit由来のDfuSe実装を使います。DFU状態確認と転送完了は行いますが、全バイト読み戻し照合は行いません。ベクターテーブル確認も、バイナリーの正しさや安全性を保証しません。未書込・途中失敗・起動しない場合は、結果を推測せずログを保存してください。

実機テストの順番

  1. 機器を外した状態で、起動→READY→中央ボタン押下と解放→画像表示→DONEを確認。
  2. 無限ループ中、待機中の中央ボタン停止を確認。最大待機分割は10msですが、実際の停止時間はドライバー処理とスケジューリングに依存し、保証値ではありません。
  3. 車輪が浮いた状態でモーター１個をAへ接続。低速・１秒から試し、方向、終了時ブレーキ、途中停止、USBを外した単独実行を確認。
  4. 超音波センサーDを接続し、10/20/50cm等の既知距離と未検出・抜線で分岐を確認。未検出値は近距離とみなさずelseへ進みます。公式ヘッダー内にcm/mm表記の不一致があり、本実装は日本語仕様と既存生成器に合わせmmとして扱っています。
  5. 電源再投入、停止後の再起動、マイブロック、ループの順に確認。結果はOS版・バイナリーSHA・機器・観察結果とともに記録。

この版は独自の中央ボタン停止処理を持ちます。SPIKE-RT自体のシステムボタン動作と競合しないかも実機で確認が必要です。

標準Hub OSへ戻す

復帰もファームウェア書き換えです。この試作版からの復帰は未検証です。PCに保存した作品を再転送する前提で進めます。

  1. SBL-RTのDFU・ログ接続を閉じ、必要なら再び上記のDFUモードにします。
  2. Pybricks Code のFirmwareメニューから Restore official LEGO firmware を選び、SPIKE Primeの画面指示に従います。これはPybricks公式が案内する標準LEGOファームウェア復帰機能です。SPIKE-RTからの復帰結果は実機確認が必要です。
  3. 標準SPIKEアプリで接続し、必要なHub OS更新に従います。認識・表示・モーターを確認してから、PCに保存した作品を再転送します。
  4. 認識しない場合は、USBケーブル、他アプリの占有、WindowsのDFUドライバーを確認し、管理者または公式サポートへ相談します。LEGOのLegacy downgradeは現行標準OS復帰と目的が違うため、代用しません。
